# 专线自动率中间表与新口径

省级流程统一计算互联网专线、MPLS-VPN专线、传输专线、视频监控MV专线四类业务。视频监控MV仅统计“行业视频MV专线”，不包含“视频监控”。四类共用有效环节口径：开通/变更有9类候选环节，拆除有6类；处理人为空或为 `/` 的环节不计入分子、分母，同单其他有效环节继续统计。分别以 `internet_`、`mpls_`、`transmission_`、`video_` 前缀写入现有 `result_orchestration_opening`。PPT按上述顺序生成各3页，原有12页自动率内容，另加2页停复机内容。

规则版本为 `3.11.0-log-no-data-slash`，记录到正式批次的 `metric_version` 以及JSON的 `automation_rule_version`、审计的 `rule_version`。产品开通量和历史汇总仍沿用自己的基础指标版本。地市计算及绘图暂未迁移到有效环节口径；共享中间表重建后，不应使用地市旧算法重算自动率。

从项目根目录运行（月份与资管文件需对应）：

```powershell
python metrics/opening/dedicated_line_metrics.py --start-month 2025-09 --end-month 2026-08 --mode both --asset-csv "data/offline_data/结束时间为8月1日-8月31日的资管专线数据清单_0902.csv"
python reporting/build_internet_line_ppt.py --month 2026-08 --section 专线自动情况 --keep-json --output outputs/monthly_report/专线自动情况_2026-08.pptx
```

`--asset-csv`为必填，输入为统计月份完结工单对应的完整资管环节明细；不会再按环节结束月份截断（早期环节可发生在月报月份之前）。

1. 读取当月订单结束的 orch_opening 原始记录。人员字段为 `/` 时保留工单及原值，不再整行剔除。开通/变更的受理、方案设计、资源分配、配置激活、开通结果审核、报结，拆除的受理、资源查询、配置激活、开通结果审核、报结，都在聚合时逐环节判断。去除首尾空格后完整等于 `/` 才按占位符处理，“自动/处理”等正常文本仍参与统计。订单号为空的记录单独剔除，原始表不修改。
2. 先在编排原始工单中筛选移机范围：订单类型为“变更”时，中间表保留调整类型为“移机”“部分移机”“内部移机”“停机”“复机”的记录，再对筛选后的订单号关联资管。最终移机指标只统计前三类，停机、复机不混入移机统计。中间表及核查CSV新增“调整类型”列，同时保留source_payload原始值；现有中间表自动补列。按订单号保留最后记录。原始MySQL表订单号本身为主键，现有原始数据不会重复。
3. CSV按二级编排工单号、环节名称分组，按结束时间取最新记录；时间相同保留CSV最后一行。结束时间缺失/非法时停止并报行号。只关联组网方案、资源反馈、组织资源释放、归档审核。资管四环节未匹配记录或处理人为空时先留空，再只对空值应用路径规则：订单类型=变更且调整类型为停机或复机时，四个资管环节均填 `/`，不再因资管空值触发日志查询；开通及全部变更的组织资源释放填 `/`；互联网专线、MPLS-VPN专线、传输专线的归档审核填 `/`（不限制订单类型）。已有处理人或 `/` 不覆盖。拆除的组织资源释放、语音专线拆除的归档审核等其他缺失保持为空。资源查询受理人不做任何补填，语音拆除也不例外。asset_matches保留真实关联记录。
4. 按月事务替换 intermediate_orchestration_orders；订单号和月份为联合主键。保存六个人员字段、资源查询受理人、四个补充环节，以及source_payload原始明细和asset_matches选中资管记录（含时间、意见、CSV行号）。月份重跑不会累加旧行。
5. 从该次构建的中间表分别读取已完成的四类专线开通/变更/拆除工单。每个环节处理人非空且不为 `/` 时计入该环节分母；其中包含“自动”计入分子。“系统管理员”作为有效人工处理人，只进分母；资源查询同样按包含“自动”判断。资管四环节也使用此规则。
6. 整体分母为各环节有效次数之和，整体分子为各环节自动次数之和，不能再用工单数乘9/9/6；全省和各地市分别累计。配置激活地市率使用配置激活自己的有效分母。分母为0时返回null，PPT显示不可统计，不伪装成0%。产品开通量及历史趋势按原流程计算。
7. 结果仍写入 result_orchestration_opening；PPT整体、各环节及资管环节地市自动率统一从数据库读取。离线互联网专线自动率JSON只保留原有非自动原因说明，原因仍是其原有历史全记录口径，与新版最新环节口径分别展示。

默认核查文件目录：outputs/orchestration_automation。包含专线自动率中间表_月份.csv、自动率剔除工单_月份.csv、专线自动率审计_月份.json。剔除文件记录订单号为空及调整类型不属于移机、部分移机、内部移机、停机、复机的变更工单，斜杠字段按列记入 slash_by_column 审计，不再整单剔除。中间表CSV保留有 `/` 的工单；审计同时记录资管匹配数、未匹配数、路径规则填 `/` 数以及待查询订单数、各环节缺失数（补齐前）。指定 --output 时核查文件改存该结果JSON的父目录。

正式指标命令默认先执行同目录的 `login_save_cookie.py`，发送短信后交互输入验证码；成功后将子系统 Cookie 原子覆盖保存到 `metrics/opening/cookie.txt`，再由 `process_log_backfill.py` 读取本地文件。登录失败立即停止，不回退旧凭证。不再接受 `--process-log-cookie`；明确不补采时使用 `--skip-process-log`。手机号沿用已验证登录脚本的 PHONE 配置，Cookie 文件及临时文件已加入 Git 忽略。

先重建当月中间表并应用路径规则，再对四个资管字段任一仍为空的订单补采；每环节取 updateDate 最新、同时间第一条，只修改空字段。查询成功但无订单或无指定环节填 `/`；处理人为空或技术异常继续留空。补齐后计算指标并重写核查CSV，不在审计中保存Cookie。每次正式重算默认重新短信登录。

旧规则已剔除的工单不能从旧中间表或旧附件恢复，首次应用新规则必须从数据库原始表重建中间表。需要保留用户附件或其他来源已有的补齐值时，应另行明确合并来源，不得假设无Cookie重算会自动保留旧补齐结果。

中间表采用按批读取、SQLite磁盘索引完成关联，避免把原始数据全量装入内存。file模式也会刷新数据库中间表，但不写正式指标结果。

中间表保留停机、复机数据并展示调整类型；移机汇总仅统计移机、部分移机、内部移机三类，停机和复机不计入移机自动率。

中间表业务范围：关联资管前，仅保留互联网专线、MPLS-VPN专线、传输专线、行业视频MV专线。其他业务不进入中间表，原始表数据不删除。四类业务的停机、复机仍保留，但不计入移机指标；空值填充及日志补齐规则不变。审计 excluded_other_businesses 记录业务范围过滤数。地市入口仅统计互联网专线，本次不会移除其业务数据，地市算法仍暂不迁移。

## 停复机自动率及本轮资管空值补填

互联网专线、MPLS-VPN专线、传输专线新增停复机指标。范围：统计月、已完成、订单类型=变更、调整类型为停机或复机；两者合并。四个环节为受理、资源查询、配置激活、报结，沿用非空且不等于 `/` 计分母、包含“自动”计分子的规则。整体按四环节有效次数加权。停复机不混入移机，行业视频MV本次不新增停复机页面。

新增指标继续写入 result_orchestration_opening：internet/mpls/transmission 前缀的 stop_resume_automation_rate（month_stage、month_city_stage、month_all_stages）及 stop_resume_activation_rate（month_city）。8月基准和环比暂为空，不显示环比，不填0%。

python reporting/build_internet_line_ppt.py --month 2026-09 --section 专线自动情况 --keep-json --output "outputs/monthly_report/专线自动情况_2026-09_含停复机.pptx"
