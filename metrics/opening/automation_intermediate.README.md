# 专线自动率中间表与新口径

从项目根目录运行（月份与资管文件需对应）：

```powershell
python metrics/opening/dedicated_line_metrics.py --start-month 2025-09 --end-month 2026-08 --mode both --asset-csv "data/offline_data/结束时间为8月1日-8月31日的资管专线数据清单_0902.csv"
python reporting/build_internet_line_ppt.py --month 2026-08 --section 专线自动情况 --keep-json --output outputs/monthly_report/专线自动情况_2026-08.pptx
```

`--asset-csv`为必填，输入为统计月份完结工单对应的完整资管环节明细；不会再按环节结束月份截断（早期环节可发生在月报月份之前）。

1. 读取当月订单结束的 orch_opening 原始记录。开通、变更工单审核受理人、方案设计处理人、资源分配受理人、配置激活处理人、开通结果审核处理人、报结人；拆除工单审核受理人、资源查询受理人、配置激活处理人、开通结果审核处理人、报结人。对应字段任一值去除首尾空格后等于 `/`，整行剔除。空值保留，其他订单类型不应用该规则。订单号为空单列剔除，原始表不修改。
2. 清洗后按订单号保留最后记录。原始MySQL表订单号本身为主键，现有原始数据不会重复。
3. CSV按二级编排工单号、环节名称分组，按结束时间取最新记录；时间相同保留CSV最后一行。结束时间缺失/非法时停止并报行号，避免误选。只关联组网方案、资源反馈、组织资源释放、归档审核。未匹配保留空值。
4. 按月事务替换 intermediate_orchestration_orders；订单号和月份为联合主键。保存六个人员字段、资源查询受理人、四个补充环节，以及source_payload原始明细和asset_matches选中资管记录（含时间、意见、CSV行号）。月份重跑不会累加旧行。
5. 从该次构建的中间表读取已完成、互联网专线的开通/变更/拆除工单。处理人包含“自动”即自动，“系统管理员”不自动；空值仍进分母。开通/变更9个环节（新增组网方案、资源反馈、归档审核），拆除6个环节（新增组织资源释放）。资源查询也按包含“自动”判断。
6. 分环节分母是该类型清洗后工单数；整体分母是工单数乘9/9/6，分子是各环节自动数之和。省级及地市都从同一中间表计算。产品开通量及历史趋势不应用此次自动率剔除规则。
7. 结果仍写入 result_orchestration_opening；PPT整体、各环节及资管环节地市自动率统一从数据库读取。离线互联网专线自动率JSON只保留原有非自动原因说明，原因仍是其原有历史全记录口径，与新版最新环节口径分别展示。

默认核查文件目录：outputs/orchestration_automation。包含专线自动率中间表_月份.csv、自动率剔除工单_月份.csv、专线自动率审计_月份.json。中间表CSV包含所有清洗后当月记录，自动率仅使用其中已完成互联网专线三类订单。未匹配四环节会降低自动率，应核查审计匹配数量。指定 --output 时核查文件改存该结果JSON的父目录。

中间表采用按批读取、SQLite磁盘索引完成关联，避免把原始数据全量装入内存。file模式也会刷新数据库中间表，但不写正式指标结果。
