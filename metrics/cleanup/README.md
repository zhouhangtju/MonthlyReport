# 按平台清理原始数据

本模块只做算数后的维护，不改变指标计算公式、筛选条件或 PPT 读取逻辑。本地离线流程已测试；最近取消跨自然月限制及Skill默认收尾的修改尚未测试。保留本地源文件和清理归档，不绕过安全检查。

## 原始文件归档

取数文件默认增加不可覆盖的本地归档：

```text
data/raw/<eoms|integration|orchestration|youshu>/<数据集>/<开始日期_结束日期>/<采集批次>/
    import_原始文件
    import.manifest.json
    original_原始Excel（终端回收快照）
    original.manifest.json
```

默认 `data` 是指定数据库所在目录；显式使用 importer 的 `archive_root` 时采用该根目录。`file` 模式以独立 file 批次归档但不建立数据库。原下载位置及结果中的文件路径不变；终端回收仍可下载到 `D:\edge_download`。

`database` 模式仍清理临时下载目录，但现在会保留持久化原始文件归档。这是本版明确的行为变化。`storage/import_data.py --no-archive` 仍允许手动导入时禁用归档，但后续清理必须找到哈希匹配的原文件，否则拒绝删除。

历史下载不会自动搬迁，已有覆盖跳过也不保证补建归档。清理旧批次前必须确认本地文件可用。终端无天然主键资料同时保留补主键后的导入文件和原始工作簿，物料名称映射也归档。

## 使用顺序

1. collector 取数入库并保留本地原始文件。
2. 使用同一数据库和周期完成全部目标指标。共享数据所有消费者成功后才进入清理。
3. 算数Skill成功验证入库结果后，默认调用 `cleanup-source-data`，按本次数据库、平台、周期和显式数据集预览。共享依赖或当前任务的后续明细消费者未完成时登记待清理，相关算数结束后再评估。
4. 检查通过且无后续明细消费者时，Skill默认添加 `--apply`，无需再次询问。用户要求保留明细或仅预览、本次算数失败或仅文件输出时不删除。脚本持有写锁归档、校验和事务删除，不要同时运行采集或算数。任务结束仍有阻塞项时报告遗留范围，不绕过检查。
5. PPT 从保留的结果表取数，不需要原始明细。

自动调用是Skill层的执行约定，不是Python算数脚本内部自动删除。直接调用清理CLI仍然默认仅预览，必须显式传 `--apply` 才删除；只运行Python算数脚本不会触发清理。

示例仅预览一体化开通数据：

```powershell
py -3.11 metrics/cleanup/integration.py --database data/quality_assessment.db --start-date 2026-08-01 --end-date 2026-08-31 --dataset integration_opening
```

同一命令增加 `--apply` 才会真正删除。另三个入口为 `eoms.py`、`orchestration.py`、`youshu.py`。每个平台可重复 `--dataset`；不指定时检查该平台全部已定义数据集，任何数据集无批次都会阻止执行，避免默默跳过。

批次跨越清理日期边界时拒绝执行。源批次是6至8月、指标也是6至8月时应按完整周期清理，不按8月标签删除整批。

## 清理范围及依赖

- 删除选中 ETL 批次对应 raw、版本、ODS、终端快照及逐行数据。
- 本平台、同周期、成功指标批次的 `ads_metric_detail` 归档后清理；失败批次明细暂留，其他平台审计明细不随之删除。
- 保留 `ads_metric_result`、`metric_run`、ETL/采集记录、编排月度汇总和质量记录、清理记录。
- EOMS 投诉需要专网/千里眼重复投诉、专线及商客新装报障结果；有数需要企宽及商客新装报障；编排新装需要专线及商客新装报障；一体化开通需要撤退率；终端回收源需要终端回收结果。
- 编排开通允许采集批次跨自然月，不因跨月而拒绝清理。仍检查批次覆盖的每个月（包括中间月份）的月度汇总及质量，保留同比基期汇总；相关结果和归档检查通过后，清理指定范围内的原始明细。
- 结果须来自选中源数据批次且晚于源数据完成。仅导入外部结果、不含有效来源关联，不能授权清理。

清理维护资料保存在 `data/cleanup_logs/<平台>/<清理批次>/`：`details.jsonl.gz` 保存被删除内容（BLOB 用base64编码），`manifest.json` 保存范围、条数、原始文件哈希和计算批次。事务失败时目录可能已存在，应以数据库 `data_retention_purge` 和命令成功返回为准，不把目录存在当成清理成功。

## 重算与限制

普通源数据可根据归档清单中的文件，用既有入口重新导入到独立库：

```powershell
py -3.11 storage/import_data.py --dataset integration_opening --file <归档文件路径> --database data/recalculate.db --period-start 2026-08-01 --period-end 2026-08-31
```

终端回收需要五类源快照。将各 original.manifest.json 对应原始文件按 `original_filename` 复制到独立暂存目录，再用三个 collector 的 `--reuse-existing --mode both --output-dir <暂存目录> --database data/recalculate.db` 补建源快照；不要只用通用 importer 后直接算数。期间不得调用真实下载来冒充恢复。

本版不提供 gzip 审计归档自动回灌，不把季度重复投诉率视作月度结果的平均值。跨源/跨月重算必须重新准备完整数据范围。

部分既有指标会读取全部源历史。为避免历史被清理后静默少算，增加保守保护：该数据集有未重新覆盖的清理周期时，要求独立库重导入；不会自动改变业务过滤口径。编排开通继续使用已有月度汇总机制。后续新月份可使用独立算数库，或补齐所需源数据；不能将这层保护关闭来绕过错误。

本版不自动 VACUUM；DELETE 后空闲页会供下一次写入复用，磁盘文件不一定立即变小。实际回收空间应另选无其他数据库任务、磁盘空间充足的维护窗口。

先在数据库副本验证清理前后结果一致、归档可重新导入、缺结果/缺文件不删除，再启用 OpenClaw 的执行模式。
