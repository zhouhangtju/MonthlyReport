# 独立数据库清理测试工具

仅新增的测试入口，不接入主流程，不修改原有代码或 Skill。需要在项目根目录用 `python -m delete.<入口>` 运行，不直接双击脚本。只依赖 Python 标准库。

## 参数

- `--database`：必填，已存在的测试数据库；路径错误不会创建空数据库。
- `--start-date` / `--end-date`：必填，选择与范围重叠的 ETL 批次；超出边界的批次阻断。允许跨自然月。
- `--run-id`：可重复，进一步限制批次；未知或范围外 ID 阻断。
- `--apply`：省略则只读预览，添加才删除。预览仍检查本地源文件和计算依赖。
- `--log-dir`：可选，默认数据库同级 `cleanup_logs`，仅实际执行写日志。

八个入口对应除编排开通外的八个 collect Skill。编排开通仍由 `prepare-orchestration-opening-monthly` 调用原有 `storage/prune_orchestration_opening.py` 归档清理，本工具不处理它。`integration_terminal_materials` 处理出库、入库、基准库、物料名称映射四类数据；其他入口处理对应的一个数据集。未出现的数据集不凭空创建，预览会列出实际选中的批次。

## 安全边界

删除选中批次的原始记录、版本、编排新装 ODS、终端源快照及行数据。只删除能定位到选中原始记录和已验证计算批次的 `ads_metric_detail`；不承诺清空全部历史算数明细。

保留 `ads_metric_result`、月度汇总及质量记录、ETL/采集/指标运行记录和全部本地文件。跨批次共享的原始记录拒绝删除，需要明确加入相关批次。后来批次的当前记录不会删除；选中批次对应的历史版本可删除。

清理前验证本地原文件或已有归档的 SHA256；没有可验证文件就阻断。**不自动备份数据库，不导出数据库明细，不重复复制原文件。** 日志不含源数据，也不能恢复删除。

所有已定义的相关指标必须有覆盖该 ETL 周期、晚于 ETL 完成且包含该源批次的成功结果。组合指标递归验证来源；终端出库未参与计算，仅检查终端结果存在及时间覆盖。此检查偏保守：仅部分月份完成、旧批次未被当前结果使用、本地中转文件已删除等情况可能阻断，不提供强制绕过。

预览退出码 0 表示通过，2 表示有阻断，1 表示执行错误。预览不代表后续任务一定不需要明细，用户仍需确认所有计划计算完成。

实际执行持有写事务并重新检查，先写 prepared 日志，再删除并记录现有 `data_retention_purge`，提交后更新 committed 日志。失败回滚；若进程在提交附近退出，prepared 日志并不证明删除未提交，应核对数据库清理记录。原始行数量按各批次记录，其他表删除数量见日志 counts。提交成功后不能事务撤销。不自动 VACUUM，数据库文件大小可能不立即减小。

旧清理工具保持不变，不要重复调用。本工具不修改 collection_run 覆盖判断；重新采集使用 `--refresh`。原计算代码没有增加缺失源数据保护，清理后重算必须先完整重新入库，不能直接使用已清理数据库重算。

## 示例

```powershell
py -3.11 -m delete.eoms_complaints --database D:/MonthlyReport/data/test.db --start-date 2026-06-01 --end-date 2026-08-31
# 明确授权删除、且预览通过后，再添加 --apply。
```

仅运行新增测试（自动创建临时数据库，不访问项目业务库）：

```powershell
py -3.11 -m unittest delete.test_common
```
