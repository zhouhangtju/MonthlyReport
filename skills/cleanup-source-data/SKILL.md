# 算数后按平台清理数据库

先阅读 `metrics/cleanup/README.md`。项目默认流程为“算数成功并验证入库结果 → 调用本技能 → 预览 → 检查通过后实际清理”。默认收尾无需再次询问是否删除；用户明确要求保留明细、仅预览或禁止清理时，以用户要求为准。仅处理本次任务确定的数据库和数据范围，不扩大到历史无关批次。本地离线流程已测试，最近取消跨自然月限制的修改尚未测试。

## 入口

| 平台 | 入口 |
| --- | --- |
| EOMS | `metrics/cleanup/eoms.py` |
| 一体化 | `metrics/cleanup/integration.py` |
| 编排 | `metrics/cleanup/orchestration.py` |
| 有数 | `metrics/cleanup/youshu.py` |

## 执行约束

1. 定位项目根目录及实际 Python 解释器，明确数据库、采集周期和数据集。不得把示例月份当默认业务周期。
2. 确认本地原始资料在 `data/raw/平台/数据集/周期/批次/` 或旧归档位置可读取。所有相关指标必须成功，不能算完第一个消费者就清理共享数据。
3. 停止其他采集、算数任务，先按平台执行不带 `--apply` 的预览。例如：

```powershell
py -3.11 metrics/cleanup/eoms.py --database data/quality_assessment.db --start-date 2026-08-01 --end-date 2026-08-31 --dataset eoms_complaint
```

4. 记录脱敏命令、周期、源批次、指标批次、原文件位置、预计删除条数和 blockers。多个数据集重复传 `--dataset`；不能通过少列数据集来跳过共享指标前置条件。
5. 预览前先合并本任务待清理范围，按平台、真实采集/计算周期分组，显式传 `--dataset`。共享源数据的依赖未完成，或当前任务还有计划中的算数需要读取该数据时，登记为待清理，继续已安排的算数，在相关算数完成后重新评估；不得用历史成功结果提前删除后续步骤需要的源数据。`blockers` 非空不执行删除，不修改代码、日期、来源关联或批次状态绕过检查；文件损坏、来源不符、执行异常等安全问题停止清理并报告，不自动重试。任务结束仍未满足依赖时报告遗留数据，不为清理擅自增加算数任务。
6. 默认算数收尾中，范围确定且预览 `blockers` 为空、无后续明细消费者时，同一命令自动增加 `--apply`。仅预览请求不执行删除；独立清理请求按用户授权范围处理。按平台顺序执行，每个成功才继续；不同平台不是一个总事务，失败时明确报告已完成与未执行部分。已清理范围不重复删除；若该范围之后重新取数，按新批次重新评估。
7. 成功后记录返回的清理归档、manifest 和 applied 状态。数据库保留结果、批次及编排月度汇总，原始资料和审计归档文件不得删除。

## 边界

- 不在普通取数或PPT请求中自动触发本技能。
- 本次算数失败、结果未入库或仅 `file` 模式时，不执行默认删除，也不能用旧结果代替本次成功。范围或周期无法确定时先询问。
- 每个算数 Skill 结束时处理可清理项并传递待清理项，整个算数任务结束时统一汇报已清理、延后和失败项。底层 Python 算数脚本本身不自动调用清理；自动衔接由执行 Skill 的 agent 完成。
- 不默认运行 VACUUM、删除历史结果或清空数据库。
- 清理后需要重算时，依照文档向独立库重新导入完整原始数据；终端回收必须补建源快照。
- Skill 日志不记录账号、密码、Token、Cookie或完整业务明细。
